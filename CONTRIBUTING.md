# Contributing to weft

weft is a composable AI rules manager. This document covers local setup, the
test layout and the commit convention the project already uses.

## Local setup

Requires Go 1.24 or later (the module targets Go 1.26.5, see `go.mod`).

```bash
git clone https://github.com/jophira/weft.git
cd weft
make build        # binary at ./bin/weft
```

## Make targets

| Target | What it does |
|---|---|
| `make build` | Compile the binary to `./bin/weft` |
| `make run` | `go run .`, pass CLI args with `ARGS="..."` |
| `make dev` | Run [`air`](https://github.com/air-verse/air), rebuilding and restarting on every Go file change |
| `make test` | Unit tests, `go test ./...` |
| `make test-integration` | Integration tests, `go test -tags integration ./...` |
| `make e2e` | CLI end-to-end tests, `go test -tags e2e ./test/e2e/...` |
| `make coverage` | Unit coverage over `./internal/...`, run through the full test suite |
| `make lint` | `golangci-lint run ./...` |
| `make clean` | Remove `./bin` |
| `make install` | `go install .` |

## Test layout

The suite is split into three tiers, each with different preconditions.

**Unit tests** (`make test`, `go test ./...`) carry no build tag and need
nothing beyond the Go toolchain. This is what CI runs on every push and PR,
across Linux, macOS and Windows.

**CLI end-to-end tests** (`make e2e`, `go test -tags e2e ./test/e2e/...`)
build the `weft` binary and drive the full source, profile, apply and
write-back lifecycle against an isolated `$HOME`. No Docker, no network. CI
runs these on every OS too, with `-count=1` to defeat the test cache, because
the suite execs the built binary as a subprocess and Go's cache key cannot see
through that boundary.

**Integration tests** (`make test-integration`, `go test -tags integration
./...`) need Docker. They spin up Gitea for git remote tests and exercise the
MCP JSON-RPC protocol loop end to end. These are not part of the CI matrix
(GitHub's macOS and Windows runners have no Linux-container Docker), so run
them locally before submitting a change that touches git remotes or the MCP
server.

Coverage (`make coverage`) instruments `./internal/...` only. `cmd/` is
excluded from the coverage figure because its Cobra `RunE` wiring is validated
by the e2e suite, not by unit tests, but `go test ./...` still runs its tests
so a regression there is still caught.

## Linting

```bash
make lint
```

Runs `golangci-lint` with the config in `.golangci.yml`: `govet`, `errcheck`,
`staticcheck`, `ineffassign`, `unused`, `gosec`, `gocritic` and `misspell`,
plus `gofmt` and `goimports` as formatters. CI runs the same linter on every
PR.

## Commit convention

```
type: (issue-number) short description
```

- `type` is one of `feat`, `fix`, `chore`, `docs`, `test`, `refactor`, `perf`.
- `issue-number` is the GitHub issue the commit addresses, in parentheses.
- The description is short, imperative and lowercase, with no trailing full stop.

```
feat: (221) add community health files
fix: (230) rebuild target watchers when an apply widens the scope
test: (224) dump watcher state when the autostart hand-off times out
```

Branch names use the same prefix as the commit type: `feat/`, `fix/`, `chore/`,
`docs/`.

Commits carry no AI attribution lines (no `Co-Authored-By: Claude`, no
`Generated by` trailer), regardless of what wrote the diff.

## Opening a pull request

1. Fork the repo and branch off `main` with a prefix matching your change:
   `fix/221-short-description`.
2. Keep commits scoped to one issue. If the change spans several concerns,
   split it into separate commits rather than one sweep.
3. Run `make test`, `make e2e` and `make lint` before pushing. Run `make
   test-integration` too if the change touches git remotes or the MCP server.
4. Open the PR against `main`. CI runs the unit and e2e suites across Linux,
   macOS and Windows, plus lint and a `govulncheck` scan.

## Reporting bugs

Use `weft bug-report` to generate a diagnostic bundle (version, environment,
`weft doctor` output and recent logs) to attach to a bug report.

For a security vulnerability, do not open a public issue. See
[SECURITY.md](SECURITY.md).
